# dl — directory bookmarks with notes

Design spec, 2026-09-21.

## 1. Purpose

`dl` bookmarks directories in numbered slots and attaches a free-form note to
each one. It replaces three zsh functions (`stl`, `cdl`, `seedl`, ~215 lines in
`~/.zshrc`) with a single Go binary plus a one-line shell integration.

The tool is not a bookmark manager. The existing notes show what it actually
is: a work-resumption notebook. Slot 7's note reads *"on fait revision-plan.md,
la on a fait jusque ex04 dans /practice, il faut continue jusqu'au bout"*. The
design follows from that — the note is the payload, the path is the index.

### Problems in the current implementation

| # | Problem | Cause |
|---|---------|-------|
| 1 | Notes are invisible; you must open vim to read one | `seedl` prints only an `ok`/`x` flag |
| 2 | A comment cannot be edited without re-saving the directory | `-c` exists only on `stl` |
| 3 | Overwriting a slot silently destroys its comment and `rm -f`s its description | `stl` lines 190-194 |
| 4 | Slots are numbers only; you must remember 7 = exam42 | no name, no search |
| 5 | 1000 aliases are created on every shell start | `for i in {1..1000}` loop |
| 6 | `vim` is hardcoded, `$EDITOR` ignored | `stl`/`cdl` |
| 7 | Dead paths are never reported | no existence check |
| 8 | The table breaks on long paths, no colour | `printf` in `seedl` |
| 9 | Depends on `jq`; writes are not locked | throughout |

All nine are addressed below.

## 2. Command surface

```
dl                        open the interactive browser (TUI)
dl <ref>                  cd into a slot          ref: 7 | exam42 | ex
dl -c, --cd     <ref>     same, explicit (scripts)
dl -z, --set    [ref]     save $PWD into a slot; no ref -> lowest free slot
      -n, --name <name>     also set the name
      -m, --note <text>     also set the note inline (replaces)
      -e, --edit            also open $EDITOR on the note
      -r, --reset           clear the name and the note
dl -s, --see              list every slot
      -l, --long            include note bodies
      -q, --quiet           paths only, one per line
dl -e, --edit   <ref>     open the note in $EDITOR
dl -r, --reset  <ref>     clear the name and note, keep the path
dl -d, --delete <ref>     remove the slot entirely
dl -p, --path   <ref>     print the path only
dl --name <ref> <name>    rename a slot
dl doctor                 report slots whose path no longer exists
dl init zsh|bash|fish     print the shell integration
dl -h, --help             overview; -h after an action for its details
dl --version
```

Migration for the user's muscle memory:

| old | new |
|-----|-----|
| `cdl7` | `dl 7` |
| `stl7` | `dl -z 7` |
| `stl7 -c "text"` | `dl -z 7 -m "text"` |
| `stl7 -d` | `dl -z 7 -e` |
| `cdl7 -d` | `dl -e 7` |
| `cdl7 -sd` | `dl -s -l` (or the TUI) |
| `seedl` | `dl -s` |

`dl 7` is four keystrokes, matching `cdl7`. This bare-argument form is the
reason the unification does not cost daily ergonomics.

### Grammar rules

- Exactly one action per invocation. Two action flags is an error.
- No action flag and no argument -> TUI.
- No action flag with one argument -> `--cd`.
- `-n`, `-m`, `-e`, `-r` are modifiers of `-z`. `-e` and `-r` are also actions
  in their own right when `-z` is absent. The parser resolves this by checking
  for `-z` first.
- `-h`/`--help` is accepted at every position and short-circuits everything.
- `-l` and `-q` are mutually exclusive on `--see`; passing both is an error.

### Exit codes

The shell wrapper propagates these, so `dl 7 && make` behaves.

| Code | Meaning |
|------|---------|
| 0 | success |
| 1 | runtime failure (unresolvable ref, empty slot, dead path, store I/O) |
| 2 | usage error (bad flag, two actions, missing argument) |
| 130 | interrupted (TUI quit with `ctrl-c`) |

A TUI quit with `q` exits 0 without writing `$DL_CD_FILE`, so the shell stays
where it was.

## 3. Data model

```go
type Slot struct {
    Slot    int       // 1..1000, the key
    Name    string    // optional, short; display falls back to filepath.Base(Path)
    Path    string    // absolute
    Note    string    // free-form, multi-line, no special first line
    Updated time.Time
}
```

There is no `comment` field. The old comment/description split was the source
of the "which one do I fill in?" hesitation; `name` now carries the short label
and `note` carries everything else.

`Name` is optional. When empty, every display path falls back to
`filepath.Base(Path)`, so no row is ever unlabelled.

## 4. Reference resolution

A `<ref>` resolves in this order:

1. All digits and within 1..1000 -> that slot number.
2. Exact case-insensitive match on `Name`.
3. Unique case-insensitive prefix match on `Name`.
4. Ambiguous prefix -> error listing the candidates.
5. Otherwise -> error.

A numeric ref never falls through to name matching, so a slot named `42` cannot
shadow slot 42.

## 5. Storage

Single file, `~/.config/dl/slots.json`, overridable with `$DL_DIR`. Notes live
inside it; there is no `descriptions/` directory.

```json
{
  "version": 1,
  "slots": {
    "7": {
      "name": "exam42",
      "path": "/home/solenopsis/.../exam5/solutions/s4/level1",
      "note": "on fait revision-plan.md\nfait jusque ex04 dans /practice",
      "updated": "2026-09-21T13:02:32+02:00"
    }
  }
}
```

- **Atomic writes**: temp file in the same directory, `fsync`, then
  `rename(2)`. A crash mid-write can never leave a truncated store.
- **Locking**: `flock` on the store for the whole read-modify-write cycle. Two
  shells saving at once no longer clobber each other.
- **Versioned schema** so a future format change can migrate rather than break.
- **No `jq` dependency.**

## 6. Migration from `~/.cdl`

On first run, if `~/.config/dl/slots.json` is absent and `~/.cdl/slots.json`
exists, `dl` imports automatically and prints a one-line summary.

```
slot    -> slot
path    -> path
comment -> note, first line
descriptions/<N>.txt -> note, appended below a blank line
name    -> empty (the user fills it in later)
```

The old directory is renamed to `~/.cdl.bak` rather than deleted. Import is
skipped silently if the destination already exists.

## 7. Overwrite semantics

`dl -z <ref>` on an occupied slot overwrites the path directly, with no
confirmation prompt. The name and the note are **kept**.

```
$ dl -z 7
slot 7 -> ~/Tocuments/wbiz/ou.you/dev/scrapping
  was ~/.../exam5/solutions/s4/level1
  name and note kept — dl -e 7 to update, dl -z 7 -r to start clean
```

The `was` line appears only when the path actually changes, so a routine
re-save of the same directory stays one line.

This fixes problem #3 not with a prompt but with non-destruction: nothing is
ever erased implicitly. Losing data requires typing `-r` or `-d`.

The TUI is the exception — `d` and `r` there do confirm, because a single
keystroke is easy to hit by accident in a way a typed command is not.

## 8. Help

Two levels.

`dl -h` is an overview: usage, the action list, the other commands, and a
pointer to per-action help. It is short enough to re-read often.

`dl <action> -h` documents one action only, with its options and real
examples:

```
dl -z, --set [ref] — save the current directory into a slot

  ref is optional: with no ref, dl picks the lowest free slot.
  An occupied slot is overwritten directly. The name and note
  are kept unless you pass -r.

OPTIONS
  -n, --name <name>   set the slot's short name
  -m, --note <text>   set the note inline (replaces the current one)
  -e, --edit          open $EDITOR on the note after saving
  -r, --reset         clear the name and the note

EXAMPLES
  dl -z                          save here, first free slot
  dl -z 7                        save here into slot 7
  dl -z 7 -n exam42 -e           save, name it, then write the note
  dl -z 7 -r -n scraping         reuse slot 7 for something else
```

Rules: `-h` works after every action; every error message points at the
relevant action help, not at the global page; bare `dl` opens the TUI rather
than printing help.

## 9. TUI

```
 dl                                                    12 slots
 ┌──────────────────────────────────┐┌────────────────────────────┐
 │   1  coloriage   ~/…/coloriage/s ││  scraping                  │
 │   4  ir-landing  ~/…/new-landing●││  ~/Tocuments/wbiz/ou.you/  │
 │   7  exam42      ~/…/s4/level1  ●││      dev/scrapping         │
 │ ▸12  scraping    ~/…/dev/scrappi●││  saved 5 days ago          │
 │   9  mev-scan    ~/…/doc-scan-co ││ ───────────────────────────│
 │   8  home        ~               ││  scraper the listing pages │
 │   6  bergens     ✗ ~/…/bergens_c ││  pagination stops at p.4   │
 │                                  ││  -> fix the retry loop     │
 └──────────────────────────────────┘└────────────────────────────┘
 ↑↓ move  ⏎ cd  / find  e edit  n name  a add  d del  ? help
```

`●` marks a slot that has a note. `✗` marks a path that no longer exists.

| Key | Action |
|-----|--------|
| `↑↓` `j` `k` `g` `G` | move |
| `⏎` | cd into the slot and quit |
| `/` | incremental filter over name + path + **note body** |
| `e` | edit the note in `$EDITOR` (TUI suspends, then resumes) |
| `n` | rename in place |
| `a` | add `$PWD` to the lowest free slot |
| `d` | delete the slot (confirm) |
| `r` | reset name and note (confirm) |
| `ctrl-d` `ctrl-u` | scroll a long note |
| `?` | key overlay |
| `q` `ctrl-c` | quit without moving |

Filtering is case-insensitive substring matching. Predictable on a set of ~12
entries, where fuzzy matching mostly produces surprises. Swapping in fuzzy
later means replacing one function.

Layout degrades by width: below 80 columns the preview pane moves under the
list; below 60, list only. Colours use `lipgloss` adaptive styles so the TUI
reads on light and dark terminals, and `NO_COLOR` is honoured.

Pressing `⏎` on a dead path shows an inline error instead of quitting.

Empty store shows a hint: `no slots yet — press a to save the current directory`.

## 10. How `cd` works

A binary cannot change its parent shell's directory. `dl init zsh` emits:

```zsh
dl() {
  local f="${TMPDIR:-/tmp}/dl-cd.$$"
  DL_CD_FILE="$f" command dl "$@"
  local rc=$?
  [[ -s "$f" ]] && builtin cd -- "$(<"$f")"
  rm -f "$f"
  return $rc
}
```

The binary writes the target directory to `$DL_CD_FILE`; the shell function
reads it and performs the `cd`.

The temp file is chosen over capturing stdout (zoxide's approach) because
capturing stdout breaks the TUI, which needs the real terminal. Here stdout and
stderr flow normally and the TUI needs no `/dev/tty` workaround.

Installation is one line, replacing 215:

```zsh
eval "$(dl init zsh)"
```

Run without the wrapper, `dl 7` prints the path and a reminder to run
`dl init` — it degrades, it does not fail silently.

## 11. Architecture

```
cmd/dl/main.go            wiring only: parse, dispatch, exit code
internal/slots/
    slot.go               Slot type, display helpers
    store.go              Load/Save/Get/Put/Delete, atomic write, flock
    ref.go                ref resolution
    migrate.go            ~/.cdl -> ~/.config/dl
internal/cli/
    parse.go              argv -> Command
    help.go               embedded help text, one per action
internal/actions/         cd, set, see, edit, reset, delete, path, doctor
internal/tui/
    model.go              state + Update (pure function)
    view.go               rendering
    keys.go               keymap
internal/editor/          editor round-trip through a temp file
internal/shellinit/       zsh.sh, bash.sh, fish.fish (go:embed)
```

Two rules hold the design together:

1. **An action is `func(s *slots.Store, out io.Writer, args Args) error`.** No
   `os.Exit` and no printing outside `main`. Every action is testable with a
   temp store and a buffer.
2. **The TUI never touches the store directly** — it calls the same actions the
   CLI calls. One behaviour to write, test and fix.

### Dependencies

`bubbletea`, `bubbles`, `lipgloss`. Nothing else.

Argument parsing is hand-written (~120 lines) rather than `pflag`, because the
grammar is unusual on two counts: `-r` means different things depending on
whether `-z` is present, and `dl 7` is a bare argument with no verb. Flag
libraries fight both; a dedicated parser describes them in twenty lines and is
tested by table.

### Editor resolution

`internal/editor` picks the first of `$DL_EDITOR`, `$VISUAL`, `$EDITOR`, then
falls back to `vi`. This fixes problem #6. The note is written to a temp file,
the editor runs attached to the terminal, and the result is read back with
trailing whitespace and trailing blank lines trimmed. A non-zero editor exit
leaves the stored note unchanged.

## 12. Testing

Test-first throughout.

| Package | Coverage |
|---------|----------|
| `slots` | round-trip, atomic write, `flock` under concurrent goroutines, missing slot |
| `ref` | number, exact name, unique prefix, ambiguous prefix lists candidates, unknown |
| `migrate` | fixture of the real `~/.cdl` shape -> expected JSON, golden file |
| `cli/parse` | argv table -> `Command`, including every error case |
| `actions` | temp store; asserts both final state and output (golden for `--see`) |
| `tui` | `Update()` is pure: key sequence -> expected state |
| `editor` | env var precedence, trimming, non-zero exit leaves the note alone |
| end-to-end | compiled binary, scripted session in a temp `$HOME` |

## 14. Phases

**Phase 1 — CLI.** store, ref, migration, every action, `dl init`, help. At the
end of this phase the binary fully replaces the zsh functions and the 215 lines
come out of `~/.zshrc`. No TUI yet, but `dl -s -l` shows notes.

**Phase 2 — TUI.** Built on already-tested actions, so it is rendering and
interaction only, no business logic.

**Phase 3 — polish.** `doctor`, zsh/bash/fish completions, CI, release.

Each phase is independently usable.

## 15. Out of scope

Deliberately excluded to keep the first version focused:

- fuzzy matching (substring is enough at this scale)
- tags, per-slot status fields, filtering by status
- syncing the store between machines
- editing notes inside the TUI (the `$EDITOR` round-trip covers it)
- more than 1000 slots
